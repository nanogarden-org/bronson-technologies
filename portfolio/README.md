# Portfolio

## Current status

This directory is both a structured capability portfolio and a searchable proof walkthrough. Some entries are documentation-only or still awaiting public demonstration runs, while others link to public repositories, external validators, or preserved third-party evidence.

Start with [`index.html`](index.html) for the human walkthrough.

Machine-readable entry points:

- [`proof-map.yaml`](proof-map.yaml) — canonical structured proof record;
- [`proof-map.json`](proof-map.json) — JSON mirror;
- [`data/search-index.json`](data/search-index.json) — searchable capability/evidence index; and
- [`llms.txt`](llms.txt) — concise agent-oriented map.

Supporting views:

- [`profile.html`](profile.html) — Robert Bronson / Robin A. Bronson professional profile and continuity;
- [`projects.html`](projects.html) — project and implementation registry;
- [`methodology.html`](methodology.html) — AI architecture, workflows, B.o.B.W., Traveler-Provenance, NanoGarden, Scout/PIRATE/THREAD, Shipping Dock, and Harbor Master;
- [`credentials.html`](credentials.html) — bridge to the canonical repository credential index and validators;
- [`evidence.html`](evidence.html) — historical third-party credibility records;
- [`LAYOUT-MAP.md`](LAYOUT-MAP.md) — portfolio topology and file roles.

Each project directory should contain a README covering:

- the problem and constraints;
- the author's role;
- system design and artifacts;
- evidence and verification;
- outcome and limitations;
- privacy and rights boundary; and
- the next test or release gate.

Use synthetic or redacted demonstrations when the original source material is protected. Do not promote a claim's maturity beyond the evidence recorded in `../evidence-index.md`.

The proof portfolio preserves a strict distinction between historical credibility, current credentials, active-development architecture, and inspectable implementation evidence.
