ILLUSTRATIVE REFERENCE METHOD · NOT A CLIENT CASE STUDY

Agentic authority and privacy review

A structured review of what an agentic workflow can observe, access, infer, delegate, and do—and how those permissions are bounded, verified, and made accountable.

REVIEW MATRIX

Separate capability from authorization

The matrix is a starting point. Actual controls must be verified in the specific environment.

DimensionReview questionEvidence to inspect
IdentityWhich principal is acting, and can the action be attributed?Identity configuration, execution logs, service-account ownership.
Data accessWhat data is available, for what purpose, and for how long?Scopes, connector permissions, data-flow records, retention settings.
DelegationCan authority be passed to tools or other agents, and is it narrowed?Tool schemas, delegated scopes, token handling, revocation tests.
ActionWhich actions are read-only, reversible, consequential, or disallowed?Tool permissions, approval gates, sandbox boundaries, test traces.
VerificationWhat must be checked independently before acceptance or execution?Validation rules, source checks, test results, exception records.
Human accountabilityWho can approve, reject, override, and review?Role definitions, approval records, escalation and override tests.
ContinuityCan the workflow be reconstructed after the event?Input lineage, version records, action logs, state-transition history.
RecoveryCan access be revoked and partial actions reconciled?Revocation tests, rollback behavior, incident and recovery procedures.

REVIEW OUTPUTS

Findings, not blanket assurances

  • Agent-to-capability and permission matrix.
  • Data-access and privacy-boundary map.
  • Unverified-control and assumption register.
  • Human authorization and escalation model.
  • Test scenarios for revocation, exceptions, and recovery.

EVIDENCE STATUS

Framework description

This is an illustrative review framework, not a completed audit, security assessment, privacy certification, or regulatory opinion. A control is only described as effective when implementation and behavior have been examined against defined evidence.

It draws on the distinct concerns represented by TurtleML's bounded-authority direction, ABCI's asynchronous communication with bounded access and authority, and the portfolio's provenance and continuity work.
